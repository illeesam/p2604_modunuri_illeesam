# 모듈 / 코바늘(Crochet) 도안 제작 정책

## 목적

기호 기반 코바늘(뜨개) 도안을 격자 편집기로 제작하고, 격자 내용을 한글 설명으로 자동 변환해주는 독립 FO 모듈. 회원이면 누구나 도안을 만들고 전체 공개로 열람할 수 있는 커뮤니티형 기능.

## 범위

- 관련 역할: 회원(도안 작성·수정·삭제), 비로그인 사용자(목록·상세 열람 가능 — 권한 구분 없이 전체 공개)
- 관련 시스템: 독립 FO 모듈(`fo-md-cb-cobanul.html`), BO 코바늘 관리 메뉴(기호/실/도안 마스터 관리)
- **2026-08-23 단순화 확정**: 소유권·권한 체크 없이 전체 회원이 서로의 도안을 조회 가능. 본인 것만 수정 가능하도록 하는 제약은 현재 버전에 없음(추후 필요 시 `memberId` 비교 추가)

## 아키텍처 요약

### 독립 FO 모듈 패턴

"FO 업무 성격은 가급적 독립적으로 만든다"는 프로젝트 방침에 따라 `index.html` 라우팅에 얹지 않고 자체 HTML 진입점(`fo-md-cb-cobanul.html`)을 가진다. 다만 ShopJoy 공통 헤더(`FoAppHeader`)·사이드바(`FoAppSidebar`)·푸터(`FoAppFooter`)·로그인 모달(`Login`)은 index.html과 동일 컴포넌트를 그대로 재사용해 로그인·알림·장바구니뱃지·링크공유·카카오공유·PDF다운로드가 동일하게 동작한다.

**부트스트랩 시 반드시 지킬 것**:
- 컴포넌트 등록은 `app.component(name, window.xxx)` — window 전역 변수명은 실제 정의부 기준 그대로 사용해야 한다(`window.foAppHeader`처럼 소문자 시작인 경우가 많음). `lib/app/foAppComp.js`의 `foRegisterComponents(app)`을 그대로 재사용하면 안 된다 — 그 함수는 `.component()`를 체이닝하는데, Vue의 `app.component(name, def)`는 `def`가 falsy(undefined)면 setter가 아니라 **getter로 오동작**해 `this` 대신 `undefined`를 반환한다. index.html은 모든 페이지 컴포넌트를 다 로드해서 문제가 없었을 뿐, 모듈처럼 일부만 로드하는 경우 체인이 끊겨 크래시한다. → 개별 `app.component()` 호출로 등록할 것
- 카카오공유/PDF다운로드/소셜로그인이 동작하려면 index.html과 동일한 외부 SDK 스크립트(Google GIS, Kakao SDK, Naver SDK, Toss SDK, html2canvas, jspdf)를 `<head>`/`<body>`에 그대로 포함해야 한다 — 빠뜨리면 헤더는 뜨지만 해당 기능만 조용히 실패한다
- 좌측 사이드바에는 "모듈" 섹션(`MODULE_ITEMS`, `components/layout/foAppSidebar.js`)에 이 모듈로의 바로가기가 등록되어 있다. 새 모듈 추가 시 이 배열에 항목만 추가하면 index.html 사이드바에도 동일하게 노출된다

### 목록/상세 분리

- `MdCbPatternListPage.js` — 검색(도안명/설명/작성자) + 일반목록(테이블)/카드형식 보기 전환(기본값: 일반목록, `localStorage`에 마지막 선택 기억) + 서버사이드 페이징
- `MdCbCobanulPage.js` — 격자 편집기(상세/편집 겸용). `?patternId=xxx` 유무와 `dtlMode`(view/edit)로 화면 상태 결정
- 두 화면 다 실제 페이지 이동(`location.href`)으로 전환한다 — 이 모듈은 해시 라우터를 두지 않는다

### 보기(view) / 편집(edit) 모드 — 전사 표준 정책 준수

프로젝트 표준(행 클릭=보기, [수정] 클릭=수정모드)을 그대로 따른다.

| 진입 경로 | 시작 모드 |
|---|---|
| 목록에서 행 클릭 / BO "열기" 링크 (`?patternId=X`) | **view** (읽기전용) |
| `+ 신규 도안` (`?view=editor`, patternId 없음) | **edit** (신규는 보기모드 개념 없음) |
| view 모드에서 [수정] 클릭 | edit |
| edit 모드에서 [취소] 클릭(기존 레코드만) | 서버 값 재조회 후 view (변경분 폐기) |

- 보기모드는 컨트롤을 숨기지 않고 `.cb-locked`(pointer-events:none + opacity 감소)로 흐리게 처리해 **비활성화**한다(전 화면 표준 — 무엇을 조작할 수 있었는지 그대로 보이되 만질 수 없게)
- 편집모드 버튼: 신규 작성은 `[초기화][저장]`, 기존 레코드 편집은 `[취소][삭제][저장]`. 보기모드는 `[삭제][수정]`
- 배너(히어로) 타이틀도 실제 모드에 맞춰 "새 도안 만들기" / "도안 편집" / "도안 상세보기"로 구분 표시

## 데이터 모델

### 계층 구조

```
md_cb_pattern (도안 마스터)
 ├─< md_cb_pattern_cell (격자 셀 — 단×코 위치별 기호/배색, 패턴당 전체 교체 저장)
 └─< md_cb_pattern_yarn (도안-실 매핑 — 이 도안에 사용된 실 목록 + 사용설명, 전체 교체 저장)

md_cb_symbol (기호 마스터 — BO 관리)
md_cb_yarn   (실 마스터 — BO 관리)
```

`md_cb_pattern_cell.symbol_id`, `md_cb_pattern_yarn.yarn_id`는 각각 `md_cb_symbol`/`md_cb_yarn`을 참조하는 논리 FK(제약 없음).

### 주요 필드

- `md_cb_pattern`: `pattern_nm`, `member_id`, `row_count`(단수), `max_stitch_count`(코수), `desc_text`(한글 설명 자동생성 캐시), `thumbnail_url`(대표이미지 — 공통 업로드 API로 받은 CDN URL 문자열, 목록 카드/썸네일에 표시), `pattern_status_cd`(DRAFT/PUBLISHED/PRIVATE — 현재 화면에서는 노출만 하고 조작 UI 없음)
- `md_cb_pattern_cell`: `row_no`, `col_no`, `symbol_id`, `color_hex`(NULL 허용 — 셀 단위 배색, 미지정 시 기본 실색)
- `md_cb_pattern_yarn`: `pattern_id`, `yarn_id`, `usage_desc`(예: "메인 색상", "포인트 색상")
- `md_cb_symbol`: `symbol_cd`(영문 약어 코드, 예: SC/HDC/DC/TR/DCINC2), `symbol_char`(격자에 표시할 문자/기호), `symbol_nm`(한글 기호명 — 텍스트 파싱의 매칭 기준), `symbol_desc`, `stitch_consume`(이 기호 1개가 전단에서 소모하는 코 수), `stitch_produce`(이 기호 1개가 생성하는 코 수 — 늘림/모아뜨기 검증 및 향후 코수 자동계산에 사용), `sort_ord`

### 기호 라이브러리 (2026-08-23 — 사용자 제공 "코바늘_기호_확정본_모음" PDF 기준 확장)

기본 8종(사슬/빼/짧은/긴/한길긴/두길긴/세길긴/네길긴뜨기) + 응용 38종(짧은뜨기 늘림·모아·걸어뜨기, 긴/한길긴뜨기 늘림·모아뜨기, 앞뒤걸어뜨기, 교차뜨기, 구슬·팝콘·솔잎·조개무늬, 특수 X자뜨기·칠보·피코·링뜨기) = 총 46종 등록.

**중요한 한계**: 이 화면은 각 격자 셀에 1~3자 텍스트만 표시하는 구조라, PDF의 손그림 도안 기호(예: 다리 여러 개로 갈라지는 부채꼴, 타원형 방울 모양)를 벡터로 완전히 재현할 수 없다. 대신 아래 **일관된 표기 규칙**으로 근사한다 — 실제 뜨기 방법의 정답은 항상 `symbol_nm`(한글명)이며, `symbol_char`는 격자 안에서 한눈에 구분하기 위한 보조 표시일 뿐이다.

| 표기 규칙 | 의미 |
|---|---|
| `T`, `T′`, `T″`, `T‴`, `T⁗` | 긴뜨기/한길긴뜨기/두길긴뜨기/세길긴뜨기/네길긴뜨기 — 프라임(′) 개수 = 기둥에 그어지는 사선(바) 개수 |
| `기본기호 + ∨` | 늘려뜨기(1코 → N코). 숫자 없으면 2코, `3`이 붙으면 3코 |
| `기본기호 + ∧` | 모아뜨기(N코 → 1코). 숫자 없으면 2코, `3`/`4`가 붙으면 3·4코 |
| `기본기호 + F` / `+ B` | 앞걸어뜨기(Front Post) / 뒤걸어뜨기(Back Post) |
| `기본기호 + X` | 교차뜨기(Cross). `→`/`←` 접미는 오른쪽/왼쪽 위 교차 방향 |
| `◆N` / `◇N` | 구슬뜨기(bobble, N코) / 변형구슬뜨기 |
| `⬢N` | 팝콘뜨기(popcorn, N코) |
| `✲N` | 솔잎뜨기(fan, N잎) |

같은 이름(`memberNm`이 아니라 `symbolNm`)으로 매칭하는 [텍스트→격자 자동 생성](#텍스트-도안-설명-역변환) 기능이 이 표를 그대로 사용하므로, 기호를 추가로 등록할 때는 반드시 `symbol_nm`을 정확한 한글 뜨기 이름으로 입력해야 한다.

### 텍스트 → 격자 자동 생성 ([📝→🧩 설명으로 격자 만들기])

기존 `[격자로부터 생성]`(격자→한글 설명)의 반대 방향. "N단: 기호명 N코, 기호명 N코, ..." 형식의 텍스트를 `fnParseDescText()`가 파싱해 격자를 자동으로 채운다 — 정규식으로 "단:" 헤더와 "기호명 N코" 세그먼트를 분리하고, `symbolNm` 완전일치로 기호를 찾아 왼쪽부터 순서대로 배치한다. "단:" 헤더가 없는 줄은 등장 순서를 단 번호로 사용. 등록된 기호명과 일치하지 않는 구간은 조용히 건너뛰고 몇 개를 건너뛰었는지만 토스트로 안내(부분 인식이라도 채워지는 게 전부 실패하는 것보다 유용). tumblbug.com/pattern_writer 같은 "뜨개 용어 텍스트 입력 → 자동 도안 생성" 제품과 동일한 컨셉.
- `md_cb_yarn`: `yarn_nm`, `color_hex`, `weight_cd`(굵기), `brand_nm`

## 편집기 주요 기능

### 격자 편집

- 클릭 1회 또는 **드래그**로 연속 칠하기/지우기 지원 — `mousedown` 시 그 칸의 현재 상태로 이번 드래그 전체의 동작(칠하기/지우기)을 판정하고, 같은 드래그 동안 `mouseenter` 되는 칸에는 매번 재판정 없이 같은 동작을 반복 적용
- 기호 팔레트 맨 앞에 **⌫ 지우개(빈칸)** 브러시가 항상 포함된다 — 이걸 선택하면 토글 판정 없이 무조건 지우기
- 모서리 4방향(상/하/좌/우)에 **[－][＋]** 버튼 쌍으로 단/코를 늘리거나 줄일 수 있다. 위/왼쪽에서 늘리거나 줄이면 기존 셀 좌표가 함께 시프트된다. 줄이는 쪽 가장자리에 있던 셀 데이터는 삭제된다(1단/1코 미만으로는 줄일 수 없음)
- 단수×코수 빠른 옵션 버튼: `10×12`, `15×20`, `20×30`, `30×40`. **신규 작성 기본값은 15×20**
- 격자 크기를 프리셋 등으로 줄였을 때 범위 밖에 남아있던 셀은 저장 시 자동으로 걸러진다(`onSave`의 range filter)

### 배색

- 4열×5행 고정 프리셋 스와치(파스텔 톤 — 원색은 눈에 피로해 부드러운 톤으로 통일, 흑/백만 원색 유지하되 검정도 `#333333`로 살짝 완화) + 직접 색상 선택(`<input type="color">`)
- BO에서 등록한 실(`md_cb_yarn`) 색상도 별도 스와치로 노출 — 클릭 시 활성 배색으로 반영되며 동시에 "이 도안에 사용된 실" 목록에 자동 추가
- 선택된 배색 스와치는 굵은 아웃라인 + 글로우 그림자 + 흰색 체크마크(✓)로 강조 표시(밝은 색도 잘 보이도록)

### 대표이미지(썸네일)

- 편집 화면 상단 툴바에 이미지 업로드 박스 — 공통 업로드 API(`coApiSvc.cmUpload.uploadMulti`)로 올리고 반환된 `cdnImgUrl`을 `thumbnailUrl`에 그대로 저장(첨부 테이블의 `attachId` 기반 조회가 아니라 URL 문자열 직접 저장 — 목록에서 N+1 조회 없이 바로 렌더하기 위함)
- 목록 화면 카드형/일반목록형 양쪽에 실제 이미지를 표시하고, 없으면 도안ID 해시 기반 그라데이션 + 🧶 아이콘으로 대체

### 한글 도안 설명 자동 생성

- `[격자로부터 생성]` 클릭 시 클라이언트에서 계산 — 같은 단(row) 안에서 연속된 동일 기호를 "기호명 N코"로 묶어 `"1단: 사슬뜨기 12코"` 형태로 조합. 저장 전 직접 수정 가능(자동생성 텍스트를 덮어써도 무방)

## 검색

목록 화면 검색은 `patternNm`/`patternDesc`/`memberNm`(작성 회원명, 조인)/`regUserNm`(등록자명, 조인) 전체를 대상으로 한다(백엔드 `QMdCbPatternRepositoryImpl.andSearchValue`). 입력 즉시 반응하지 않고 [조회] 버튼/Enter 입력 시에만 재조회(프로젝트 표준 검색 정책).

## 백엔드 구조

패키지는 `com.shopjoy.ecadminapi.md.cb.*` — 다른 도메인처럼 `base`/`bo`/`fo` 레이어로 나누지 않고 **flat 구조** (권한 구분 없이 전체 조회로 단순화하기로 확정했기 때문). API 엔드포인트는 `/api/md/cb/*`.

- `MdCbPatternController` — 표준 CRUD + `/{id}/cells`(격자 전체 교체), `/{id}/yarns`(재료 전체 교체) 서브리소스
- `MdCbPatternCellService`/`MdCbPatternYarnService` — 개별 CRUD 없이 도안 단위 `replaceAll()`(delete-then-insert)만 제공. 프론트가 편집 화면의 현재 상태 전체를 매 저장마다 통째로 보낸다
- `QMdCbPatternRepositoryImpl` — `memberNm`(회원 조인)·`regUserNm`(등록자 조인) 검색 지원

## 제약사항

- 소유권 체크 없음 — 로그인한 아무 회원이나 다른 회원의 도안을 열람·수정·삭제 가능(2026-08-23 의도적 단순화). 실서비스 전환 시 `memberId` 비교 가드 추가 필요
- `md_cb_pattern_cell`/`md_cb_pattern_yarn`은 부분 업데이트 API가 없다 — 저장 시 항상 전체 교체(대량 도안·잦은 자동저장 시나리오에는 비효율적일 수 있음)
- `pattern_status_cd`(DRAFT/PUBLISHED/PRIVATE) 값은 존재하지만 화면에서 변경할 UI가 없어 항상 DRAFT로 고정됨
