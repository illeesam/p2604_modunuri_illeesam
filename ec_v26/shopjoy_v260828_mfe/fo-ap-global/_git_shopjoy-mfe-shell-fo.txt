shopjoy-mfe-shell-fo

관리단위: 마이크로 도메인 — FO(사용자 페이스) 메인프레임(셸). BO 쪽
          bo-ap-global(shopjoy-mfe-shell)과 대응하는 FO 전용 셸이다.
현재 위치: shopjoy_v260828_mfe/fo-ap-global/  (컨테이너 폴더 바로 밑, 모든
          fo-* 도메인 레포와 완전한 형제)

⭐ BO와 다른 점 — FO는 대메뉴/탭 라우팅이 없고 `?page=xxx` 쿼리스트링 기반
  단일 페이지 라우팅이다(shopjoy_v260406/lib/app/foAppBase.js 참고, 2026-08-22
  해시(#page=)→쿼리스트링 전환). 그래서 지연로드 인프라도 BO보다 단순하다:
  - `lib/mfe/foMfeRegistry.js` — pageId → comp 평평한 맵(menuKey/group 없음).
    BO의 mfeRegistry.js와 동일한 ensureXxxLoaded 패턴(2026-08-29 버그 수정 포함).
  - `lib/mfe/foMfeCatalog.js` — pageId → 담당 폴더 목차(코드 없음). BO의
    mfeCatalog.js와 같은 역할이나 menuKey/group 인자가 없다.
  - `lib/mfe/foMfeShell.js` — shopjoy_v260406/lib/app/foAppBase.js 를 거의
    그대로 재사용한다(BO의 mfeShell.js처럼 새로 쓴 게 아님) — 장바구니/좋아요/
    비교함/토스트/API로그패널/테마/모바일메뉴 같은 진짜 화면 상태가 많아서,
    그 로직은 원본 그대로 두고 "페이지 컴포넌트 해석"과 "navigate() 지연로드"
    2곳만 레지스트리 기반으로 바꿨다(foMfeShell.js 상단 주석 참고).

포함 경로: assets/(cdn pkg: vue/vue-demi/pinia/axios/postcode/marked/
          toastui-editor/html2canvas/jspdf + css: fo-global-style01~03),

          pages/base/(fo{Error401,Error404,Error500}.js — 셸이 항상 들고 있음),
          mfe.html(메인 진입점)

⭐ 독립 FO 모듈 공용 의존(2026-08-29 추가) — fo-md/cb, fo-md/sg 처럼
  foMfeShell.js 라우팅 밖의 완전 독립 HTML 앱(fo-md-*-*.html)들이 공유하는
  파일: `lib/app/foModuleShell.js`(index.html의 foAppBase.js 축약판 — theme/
  auth/사이드바/토스트/컨펌만), `components/comp/BoComp.js`(그 모듈들의
  Login.js 서브모달이 쓰는 bo-multi-check-select, FO/BO 공용 위젯),
  `assets/css/fo-md-module-style.css`(모듈 공통 스타일). 각 모듈 전용 파일
  (페이지 컴포넌트, 전용 CSS, mdCbApiSvc.js/mdSgApiSvc.js 등)은 이 셸이 아니라
  fo-md/cb/, fo-md/sg/ 각자의 폴더 안에 있다 — 자세한 건 그쪽 git 마커 참고.

FO 페이지 파일도 BO와 동일하게 `export default`(ES 모듈) 방식이다(2026-08-29
  통일 — 처음엔 "FO 도메인들(fo-ap-home/fo-ec-pd/fo-ec-od/fo-ec-my/fo-ec-cm/fo-zd)은
  서로 페이지 이름이 하나도 안 겹쳐서 BO에서 ES 모듈 전환의 계기가 됐던 '같은 이름을
  여러 폴더가 나눠 쓰다 충돌' 문제가 애초에 없다"고 보고 classic `window.ComponentName`
  방식을 유지했었지만, 프로젝트 전체 일관성을 위해 BO와 같은 방식으로 다시 통일했다).
