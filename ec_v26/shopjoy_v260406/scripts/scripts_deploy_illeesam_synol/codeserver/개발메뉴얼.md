# ShopJoy code-server 개발 환경 세팅 매뉴얼

이 문서는 DS920+ NAS의 code-server(브라우저용 VS Code) 인스턴스에 처음 들어왔을 때,
소스를 받아서 실제로 빌드/배포까지 할 수 있는 상태로 만드는 전체 순서를 따라하기
방식으로 정리한 것입니다. (2026-09-07 기준, 1~5번 인스턴스 공통)

- 접속 주소: `http://illeesam.synology.me:2510N` (N=인스턴스 번호, 예: 1번=25100)
  ⚠ **http 입니다. https 아닙니다** — code-server가 SSL 없이 순수 HTTP로 서빙합니다.
- 로그인 비밀번호: `1` (5개 인스턴스 공통 고정값)
- 이 터미널은 **기본적으로 root 권한**입니다 — `sudo` 안 붙여도 됩니다.

---

## 1. 패키지 목록 갱신 (필수, 제일 먼저)

```bash
apt update
```
(root라서 `sudo` 없이 바로 됩니다. 이거 안 하면 다음 단계에서 "패키지 없음" 에러가 남)

## 2. Node.js + npm 설치

```bash
apt install -y nodejs npm
node -v && npm -v
```

## 3. JDK 17 설치 (⚠ JRE 아님, JDK)

Gradle 빌드는 컴파일러(`javac`)가 필요해서 JRE만으로는 안 됩니다.

```bash
apt install -y openjdk-17-jdk
java -version   # 17.x 인지 확인
```

## 4. 소스 코드 클론 — 반드시 얕은 클론(`--depth 1`)으로

```bash
cd ~/workspace
git clone --depth 1 --branch main https://github.com/illeesam/p2604_modunuri_illeesam.git
cd p2604_modunuri_illeesam
git status   # "On branch main" + "up to date with 'origin/main'" 확인
```

**⚠ 옵션 없이 `git clone`만 하면 실패합니다.** 이 저장소는 87,440개 오브젝트짜리
모노레포라, 전체 클론 시 delta 해석/체크아웃 막바지에서 매번 정확히 같은 지점(4%,
2709/67716)에서 프로세스가 죽습니다(`git fsck`로 확인하면 dangling commit + 파일 0개
상태). 정확한 원인은 못 찾았지만 `--depth 1`(얕은 클론)으로 우회하면 확실하게 됩니다.
나중에 전체 히스토리가 필요해지면:
```bash
git fetch --unshallow
```

## 6. GitHub push 인증 — `gh auth login` (디바이스 코드 방식)

```bash
# gh 없으면 먼저 설치
type -p gh >/dev/null || (curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg | dd of=/usr/share/keyrings/githubcli-archive-keyring.gpg \
&& chmod go+r /usr/share/keyrings/githubcli-archive-keyring.gpg \
&& echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" > /etc/apt/sources.list.d/github-cli.list \
&& apt update && apt install gh -y)

gh auth login
```
질문에 이렇게 답할 것:
- `What account do you want to log into?` → **GitHub.com**
- `What is your preferred protocol?` → **HTTPS**
- `Authenticate Git with your GitHub credentials?` → **Yes**
- `How would you like to authenticate?` → **Login with a web browser**

터미널에 `Your Code: XXXX-XXXX` 코드가 뜹니다 — 아무 브라우저에서
https://github.com/login/device 열어서 그 코드 입력하면 인증 완료됩니다.
(Claude Code CLI 로그인과 달리 이 방식은 localhost 콜백이 필요 없어서 이 환경에서도
문제없이 됩니다.)

## 10. 여기까지 하면 배포 명령어 사용 가능

```bash
# 5개 shopjoy 앱 배포 (deploy/ 워크스페이스) — 스크립트명 앞 'apps DEPLOY ' 접두어, 공백 때문에 따옴표 필요
cd deploy
npm run "apps DEPLOY ecBeBo-22300 (springboot)"      # ecBeCdn-22400 / ecFeBo-22000 / ecBeRedis-22379 / ecBeGateway-22099 도 동일 패턴

# 정지/삭제/상태확인 (stop/·delete/·ps/ 워크스페이스, 앱 이름은 포트 없이. 접두어는 apps STOP/DELETE/PS)
cd ../stop && npm run "apps STOP ecBeBo"
cd ../delete && npm run "apps DELETE ecBeBo"
cd ../ps && npm run "apps PS ecBeBo"

# code-server 자기 자신(1~5번) 배포/정지/삭제/상태확인 (codeserver/ 워크스페이스, 접두어 codeserver DEPLOY/STOP/DELETE/PS)
cd ../codeserver
npm run "codeserver DEPLOY deploy1-25100 (codeserver)"   # ~ deploy5-25500
npm run "codeserver STOP stop1"             # ~ stop5
npm run "codeserver DELETE delete1"         # ~ delete5
npm run "codeserver PS ps1"                 # ~ ps5
```

⚠️ **지금 작업 중인 그 인스턴스 번호로 `deploy{N}`/`stop{N}`/`delete{N}`을 실행하면
자기 자신의 세션이 그 자리에서 끊깁니다** — 항상 다른 번호이거나, 지금 안 쓰는 인스턴스를
대상으로 할 것. 데이터(`/config`)는 안 지워지니 다시 접속하면 그대로 남아있습니다.

## 알아두면 좋은 것들

- **비밀번호가 로그인 안 될 때**: `env/ecCodeServer{N}.env`(NAS 전용, git 미추적) 파일에
  실제 값이 뭔지 SSH로 직접 확인. 예전에 랜덤값이 남아있어서 안 맞은 적 있었음.
- **code-server 버전 확인**: 웹 UI 우측 하단 code-server 아이콘 클릭 → About. `code-server`
  버전과 `Code`(내장 VS Code 코어) 버전이 따로 표시됨.
- **`:latest` 태그라 매 배포마다 최신 이미지로 자동 갱신됨** — 특정 버전 고정 아님.
- **root 권한 기본 제공** — PUID/PGID=0으로 배포되어 있어 `sudo` 불필요.
