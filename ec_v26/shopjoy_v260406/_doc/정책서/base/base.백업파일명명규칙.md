# 임시 백업 파일 명명 규칙

실험적 변경(리다이렉트 테스트, 위험한 리팩터링 등) 전에 원본 파일을 그대로 남겨두는 **임시 백업 파일**의 이름 규칙. Git 커밋과는 별개로, "되돌릴 수도 있는 작업 전에 원본을 눈에 보이는 파일로 남겨두는" 용도다.

## 형식

```
{원본 파일명 전체(확장자 포함)}.{YYYYMMDD}_{HHMM}_{용도}.txt
```

- `{원본 파일명 전체}` — 확장자까지 포함한 원본 파일명 그대로 (예: `index.html`)
- `{YYYYMMDD}_{HHMM}` — 백업 시점의 날짜 8자리 + 시각 4자리(시분), 밑줄로 구분
- `{용도}` — 왜 백업했는지 짧게 (예: `backup`, `beforeRedirectTest`, `beforeRename`)
- 항상 `.txt` 확장자로 끝난다 — 원본이 `.html`/`.js`든 상관없이 `.txt`로 저장해 브라우저·빌드 도구가 실제 리소스로 오인해 로드하지 않게 한다

## 예시

```
index.html.20260822_0627_backup.txt
CmDashboardItemMng.js.20260821_1930_beforeSyncFix.txt
```

## 적용 시점

- 실험적 변경을 시도하고 "괜찮으면 적용, 아니면 되돌리기" 식으로 진행할 때
- 되돌릴 파일이 많거나 구조가 복잡해서 `git diff`/`git checkout` 만으로는 되짚기 번거로울 때

## 정리

- 실험이 확정(적용)되면 백업 파일은 삭제한다 — 저장소에 영구히 남겨두지 않는다
- Git으로 이미 추적되는 파일의 사소한 수정에는 이 백업 방식을 쓰지 않는다 (커밋/브랜치로 충분) — 이 규칙은 **아직 커밋 안 된 실험적 시도**나 **브랜치를 새로 파기 애매한 짧은 트라이얼**에 한정한다
